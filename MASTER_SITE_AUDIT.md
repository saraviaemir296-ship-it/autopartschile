# MASTER_SITE_AUDIT.md — AutopartsChile.cl

Auditoría integral iniciada 2026-08-12. Este documento se actualiza por ciclos, sin sobrescribir historial. Metodología: cada fila tiene evidencia verificable (archivo/sha/comando), no opinión. Donde no hay evidencia directa (requiere navegador real, Lighthouse, o acceso a GA4/GSC/Merchant Center en vivo) se marca `PENDIENTE DE VERIFICACIÓN` explícitamente — no se inventa un resultado.

## Nota metodológica honesta

El pedido original de esta auditoría (40 secciones: seguridad, pagos, UX, CRO, mobile, performance, accesibilidad WCAG 2.2 AA, analytics, legal, arquitectura, escalabilidad a 20 marcas) es del tamaño de un engagement de consultoría de varias semanas con un equipo completo. Este ciclo cubre lo que es verificable de forma segura y con evidencia real desde el repositorio (seguridad de configuración, pagos, SEO/datos estructurados, arquitectura de datos) porque son auditables por inspección de código sin riesgo. Lo que requiere interacción visual real con el sitio en un navegador (UX, CRO, mobile, accesibilidad, performance/Core Web Vitals) queda marcado como pendiente para el próximo ciclo, donde se puede usar el navegador conectado para capturar evidencia real en vez de inferir desde el código.

## Áreas explícitamente NO auditadas este ciclo (requieren evidencia real, no inferencia)

- **Performance / Core Web Vitals (LCP, INP, CLS, TTFB)**: requiere una prueba real en navegador (Lighthouse o PageSpeed Insights) contra la URL en vivo. No se ejecutó este ciclo.
- **UX/UI visual, mobile-first, CRO**: requiere screenshots reales del sitio renderizado (desktop y ~390px mobile). No se tomaron capturas este ciclo.
- **Accesibilidad (WCAG 2.2 AA)**: requiere inspección con lector de pantalla o herramienta axe/Lighthouse contra el DOM renderizado, no solo el HTML fuente.
- **Búsqueda interna**: requiere probar consultas reales contra el buscador del sitio en vivo.
- **GA4 / Search Console**: sigue bloqueado por falla de la extensión de Chrome (ver `SEO_AGENT_LOG.md`).
- **Edge Functions de Supabase** (`mp-create-preference`, `webpay-create-transaction`, `webpay-confirm`, etc.): no se leyó su código este ciclo — ahí podría vivir lógica de validación, rate limiting o el ambiente real de Transbank (integración vs producción).

## Severidad de hallazgos abiertos (resumen)

- **P0 (posible)**: Webpay Plus podría estar en ambiente de prueba mostrado como productivo — requiere confirmación del usuario, no del código.
- **P1**: 119 productos reales no sincronizados a `products.json`/feed/Merchant Center; schema faltante en página de 55 productos.
- **P2**: CSP con `unsafe-inline` (deuda técnica aceptada, requiere build step para resolver de raíz).
- **P4**: 4 archivos de prueba huérfanos (bloqueado por herramienta).
